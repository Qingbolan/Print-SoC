# 打印机详情与进度

2026-11-09，基于上游 `127a77774e250c6ac918165ce736bc1e109e8b7c` 的 `StatusActivity` 原始 lpq 展示和 `PrintingActivity` 阶段/上传字节回调实现。复用行为设计，不复制旧 Java、JAR 或下载流程。

## 已实现

- 打印机列表使用实时 store，初始目录状态为 Unknown，不把静态目录当作在线探测结果。
- `print_get_queue_snapshot` 新增队列级状态、原始输出、任务行、采样时间和解析完整性标记。旧 `print_check_printer_status` 仍返回任务数组。
- 抽屉与对话框共享 `QueueDetails`：自动刷新、手动刷新、队列任务的 rank/owner/id/file/size、原始诊断。未知响应不宣称在线；常见缺纸、暂停、离线和错误优先于任务数量。
- 队列变体按钮现在实际切换当前查看和操作的队列。
- PrintJob 增加可选 progress 字段，旧历史无需新字段。阶段包含 Preparing、Uploading、Formatting、Submitting、Accepted、SubmissionUnknown、LeftQueue。
- 上传使用实际已写入的字节，保留 SCP 文件长度和接收确认校验。100% 仅代表字节已传送，不代表服务器确认或纸张打印完成。
- 提交弹窗和作业详情轮询本地任务进度，不等待 SSH 查询锁。网络轮询在阻塞工作线程执行。
- 提交前可取消准备；上传在块边界检查，转换完成后在 lpr 前再次检查。转换进程不承诺立即中断。取消状态不会被工作线程错误覆盖。
- 进入 Submitting 后禁止准备阶段取消；必须等到远端队列 ID 可用于取消。状态切换和取消判断共享任务锁。
- lpr 成功后为 Queued；只有 lpq 的 active 行显示 Active in spooler。精确匹配队列 ID，不使用原始行子串匹配。
- 只有可识别的完整队列结果才可判定任务已离开队列。内部保留 Completed 枚举以兼容公共接口，UI 标为 Left queue，并明确不代表实体打印成功。
- 查询使用提交时实际选择的单/双面队列，避免查错后提前判为离队。结果不明不会自动重发打印。
- 手动和后台目录刷新共用一个刷新流程；页面隐藏时暂停发起周期查询。

## 边界

lpq 不提供实际已打印页数、剩余时间、纸张/耗材百分比；界面不编造这些数据。目录中的位置、型号和纸张能力仍是静态元数据。原始诊断始终可查看，解析器不承诺识别所有服务器方言。未知或异常响应保留任务原状态。

此次未增加取消其他设备提交任务的入口，也未声称能停止已经输出的纸张。配额普通入口、Office 移动转换等仍在独立实施计划中。

## 界面整理

详情抽屉与弹窗共用 `PrinterDetails`：顶部位置与模式选择，中部队列和任务列表，底部固定默认/使用操作。型号与位置导航折叠展示，服务器原文置于技术详情，取消重复状态区和常驻技术说明。移动窄屏底部操作上下排列。详情和进度使用现有 locale，用户状态标签采用简短表达；上传仍只报告实际字节进度，任务离队时才显示取件核对提示。

已在离线浏览器检查详情展开、单/双面切换及中英文切换；未做真实手机设备验收。TypeScript、设计检查与 9 个前端测试通过。
